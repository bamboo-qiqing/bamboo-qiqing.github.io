# 配置 Codex

## 从控制台生成配置

在 API 密钥列表打开 **使用密钥**，选择 **Codex**，再按系统标签复制完整配置。控制台生成的内容会匹配当前分组和认证方式，是唯一推荐来源。

## 配置位置

| 系统 | 常见目录 |
| --- | --- |
| macOS / Linux | `~/.codex/config.toml`、`~/.codex/auth.json` |
| Windows | `%USERPROFILE%\.codex\config.toml`、`%USERPROFILE%\.codex\auth.json` |

如果目录不存在，按弹窗提示创建；不要把完整文件上传到工单或公开仓库。

## 保存并验证

1. 复制控制台为当前系统生成的内容。
2. 完全退出 Codex CLI 或 Desktop，再重新打开。
3. 新建一个任务，发送只读的小请求：

   ```text
   请回复“连接成功”，不要读取或修改任何文件。
   ```

4. 请求成功后再开始正常工作。

Codex Desktop 可能缓存旧配置，只切换窗口不会重新加载。若控制台提供 **API Key Mode**，按弹窗推荐模式操作；不要自行混用两种模式。

## 仍未生效时

- 检查密钥状态为活跃，且已绑定可用的 Codex 分组。
- 重新从 **使用密钥** 复制，不要手动改 `base_url`、认证字段或模型名。
- 完全退出所有 Codex 进程，确认旧环境变量没有覆盖新配置。
- 记录状态码后查看[常见错误](/relay/troubleshooting)。

::: warning 配置文件保密
`auth.json` 和包含 `env_key`/Key 值的配置文件都不可提交到仓库。报告问题时只贴去掉密钥后的字段名和错误堆栈。
:::
