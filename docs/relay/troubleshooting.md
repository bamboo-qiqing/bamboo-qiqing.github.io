# 常见错误

先确认三件事：服务账号能正常登录、密钥状态为活跃、密钥已经绑定可用的 Codex 分组。再按下面的表现定位。

| 表现 | 检查位置 | 处理方法 |
| --- | --- | --- |
| `401 Unauthorized` | 密钥是否缺失、过期或复制错误 | 回到密钥列表重新打开 **使用密钥**；仍失败就轮换一把新密钥。 |
| `403 Forbidden` | IP 限制、密钥状态和分组权限 | 暂时关闭不确定的 IP 限制，确认分组后再做一次最小请求。 |
| `429 Too Many Requests` | 速率限制、并发和时间窗口额度 | 降低并发，等待窗口恢复；不要连续创建大量密钥重试。 |
| 额度耗尽 | 密钥额度、有效期和账户余额 | 换用仍有额度的分组或联系管理员确认限制。 |
| 模型不可用 | 当前分组的模型列表 | 在控制台选择可用模型，不要只改客户端里的模型名。 |
| `5xx` 或网关错误 | 发生时间、请求类型和服务状态 | 稍后重试；持续失败时提供下面的最小诊断信息。 |
| 流式输出中断 | 网络、代理和客户端模式 | 先重新复制普通配置，确认基础请求成功后再检查网络。 |
| 修改配置后仍走旧地址 | Codex 进程和旧环境变量 | 完全退出 CLI/Desktop，重新打开并新建任务。 |

## 反馈问题时提供

```text
发生时间（含时区）：
客户端：Codex CLI / Codex Desktop
操作系统：
分组：
API Key 末四位：
状态码：
错误消息：
```

不要发送完整 API Key、账号邮箱、配置文件、工作区绝对路径或包含业务数据的请求正文。
