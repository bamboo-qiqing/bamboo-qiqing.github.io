# API 中转故障排查

先确认三件事：服务地址可打开、密钥处于活跃状态、密钥已经分配到 Codex 分组。再根据状态码处理。

| 表现 | 优先检查 | 处理方法 |
| --- | --- | --- |
| `401 Unauthorized` | Key 是否缺失、过期或复制错误 | 重新从“使用密钥”复制；必要时轮换新 Key |
| `403 Forbidden` | IP 限制、密钥状态或权限 | 暂时移除错误的 IP 限制，并确认分组权限 |
| `429 Too Many Requests` | 并发、时间窗口额度或上游限流 | 等待窗口重置，减少并发，确认是否为单 Key 限制 |
| 额度耗尽 | Key 额度、账户余额和时间范围 | 更换有额度的分组或等待管理员处理 |
| 模型不可用 | 当前分组模型列表 | 在控制台查看可用模型，不要猜测模型名 |
| `5xx` 或网关错误 | 服务状态、时间点和请求类型 | 重试一次；持续失败时提供脱敏诊断信息 |
| 流式输出中断 | 网络、代理、超时和 WebSocket 模式 | 先退回普通 Responses 配置，再比较结果 |
| 修改配置后仍走旧地址 | Codex 进程缓存或旧环境变量 | 完全退出并重启，检查当前 Shell 的环境变量 |

## 配置未生效的最小检查

```bash
env | grep -E 'SUB2API|OPENAI|CODEX'
```

Windows PowerShell：

```powershell
Get-ChildItem Env: | Where-Object Name -Match 'SUB2API|OPENAI|CODEX'
```

不要把上述命令的完整输出直接发到公开渠道；环境变量值可能就是 API Key。

## 仍然无法解决时

提供[用量与额度](/relay/usage)中的诊断模板，附上脱敏后的配置字段和状态码。不要反复删除并创建密钥，这会让问题更难追踪。
