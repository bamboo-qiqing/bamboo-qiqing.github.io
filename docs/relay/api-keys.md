# API Key 管理

API Key 是客户端访问中转服务的唯一凭据。一个密钥可以绑定一个分组，并可单独设置状态、有效期、额度和 IP 访问限制。

## 常用操作

| 操作 | 适用场景 | 注意事项 |
| --- | --- | --- |
| 创建 | 为一台设备或一个项目分配独立凭据 | 建议用设备/项目命名，不要多人共用 |
| 使用密钥 | 获取 Codex 当前版本配置 | 只在可信设备上复制 |
| 更换分组 | 切换到管理员分配的其他模型组 | 已有请求可能继续计入旧分组的记录 |
| 停用 | 临时阻断调用 | 停用后客户端通常会收到 `401` 或 `403` |
| 删除 | 永久废弃密钥 | 删除前确认没有其他设备依赖 |

## 额度与有效期

- **额度限制**：限制该密钥最多消费的金额，`0` 通常代表不限制，具体以界面提示为准。
- **时间窗口限制**：按 5 小时、1 天或 7 天限制消费时，达到窗口上限后需要等待重置。
- **有效期**：过期密钥不能继续调用，即使账户仍有余额。
- **状态**：活跃、停用、额度耗尽和已过期需要分别处理。

## IP 限制

如果管理员允许配置 IP 白名单或黑名单：

1. 每行填写一个 IP 或 CIDR。
2. 先确认客户端出口 IP，再保存限制。
3. 修改后用同一设备做一次最小请求验证。

配置错误通常表现为 `403`。远程办公、代理或移动网络可能导致出口 IP 变化。

## 密钥轮换

怀疑密钥泄露时，先创建新密钥并完成 Codex 配置，再停用旧密钥。确认新密钥工作后删除旧密钥。不要把新旧密钥同时写入公开脚本或仓库。
